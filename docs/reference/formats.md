# File formats

This page lists every key the catalog's files use. The formats are defined by [blis-schemas]([[catalog.schemas_tree]]), and the catalog's CI checks every file against version [[catalog.validate_pin]] of them. Where this page and the schema source disagree, the schema is right.

Three conventions hold across the files:

- **A file's name is its identity**, except for `model.yaml`, which states its name and must match its directory. A `name` key in a chip, fabric or workload file is rejected.
- **Unknown keys are errors.** The exception is a comment key: `_comment`, or a key that begins with `_comment_`. Comment keys hold the provenance prose and are ignored by every program that loads the data. They are accepted in chip, fabric and workload files and inside a storage tier's mapping; they are not accepted in `model.yaml` or at the top level of `devices/storage.yaml`.
- **Each key has one unit.** The tables below give it. Storage-tier keys spell their units out (`_mb_s`, `_us`). MB, GB and TB are decimal; GiB is 2<sup>30</sup> bytes.

## Models

A model entry is the directory `models/<name>/`, holding three files.

`config.json`
:   The vendor's config, copied byte for byte. The validator checks only that it is a non-empty JSON object; the deriver interprets its keys.

`model.yaml`
:   Which model this is and where the config came from.

    | Key | Required | Meaning |
    | :--- | :--- | :--- |
    | `name` | yes | the entry's name; must equal the directory name |
    | `source.provider` | yes | where the config is hosted; `huggingface` for every entry |
    | `source.repo` | yes | the repository on that host, with its original capitalization |
    | `source.revision` | yes | the full commit hash the config was taken from |
    | `source.retrieved` | no | the date it was taken, `YYYY-MM-DD` |

`graph.yaml`
:   The model graph, generated by `scripts/derive_graph.py`; never edited by hand. [Model graphs](../concepts/model-graphs.md) explains its structure, and [`spec/model/graph.go`]([[catalog.schemas_tree]]/spec/model/graph.go) defines it.

## Chips

`hardware/<name>.yaml`, one chip per file. Figures are nominal and per GPU.

| Key | Unit | Required | Meaning |
| :--- | :--- | :--- | :--- |
| `Provenance` | | yes | `vendor_spec` or `derived`; see [Provenance](../concepts/declared-facts.md#provenance) |
| `TFlopsPeak` | TFLOP/s | yes | dense BF16 peak; positive |
| `TFlopsFP8` | TFLOP/s | always written | dense FP8 peak; `0` on a chip without native FP8, otherwise greater than `TFlopsPeak` |
| `TFlopsNVFP4` | TFLOP/s | no | dense NVFP4 peak; omitted where the format is not native |
| `BwPeakTBs` | TB/s | yes | HBM bandwidth; positive |
| `MemoryGiB` | GiB | yes | HBM capacity; positive |
| `IntraNodeBwGBps` | GB/s | yes | intra-node link (NVLink where present), one direction; positive |
| `SMCount` | count | yes | streaming multiprocessors enabled on this chip; positive |
| `GPUsPerNode` | count | no | GPUs in one node; stated only for rack-scale chips |
| `GPUsPerRack` | count | no | GPUs in one rack-scale NVLink domain; when both are given, a multiple of `GPUsPerNode` |
| `IntraRackBwGBps` | GB/s | no | bandwidth between nodes in the rack, one direction; requires `GPUsPerRack` |

*Always written* means the schema would accept the key's absence, but every entry writes it, even where its value is `0`. A missing key and a `0` decode alike; writing the `0` records that the chip lacks the format.

## Fabrics

`networks/<name>.yaml`, one fabric class per file.

| Key | Unit | Required | Meaning |
| :--- | :--- | :--- | :--- |
| `Provenance` | | yes | as for a chip |
| `InterNodeBwGBps` | GB/s | yes | nominal bandwidth per GPU, one direction: the line rate of the network cards serving one GPU, in GB/s; positive |
| `RDMA` | | no | `true` when the fabric moves data without passing it through the CPU |

## Workloads

`workloads/<name>.yaml`, one workload per file. All values are tokens per request.

| Key | Required | Meaning |
| :--- | :--- | :--- |
| `prefix_tokens` | no | length of the prefix requests share; `0`, the default, means none; not negative, and at most `prompt.tokens` |
| `prompt.tokens` | yes | mean prompt length; at least 1 |
| `prompt.tokens_stdev` | no | standard deviation; not negative |
| `prompt.tokens_min`, `prompt.tokens_max` | no | bounds; the mean lies between those given |
| `output.*` | | the same four keys, for the output |

## Storage tiers

`devices/storage.yaml`, one file holding every tier, keyed by tier name.

| Key | Unit | Meaning |
| :--- | :--- | :--- |
| `read_bandwidth_mb_s` | MB/s | sustained read bandwidth; positive |
| `write_bandwidth_mb_s` | MB/s | sustained write bandwidth; positive |
| `base_latency_us` | µs | fixed cost of one transfer; positive |
